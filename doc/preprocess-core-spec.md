## キー取得機能の基本仕様

レシピの `orderIds` のようなプレースホルダを埋めるための「更新対象キーの取得」には、
CSVから直接取る方法（`preprocess-csv`）と、DBに問い合わせる方法（`preprocess-lookup`）の
2種類がある。

### from: CSV

- **キー項目のみ指定で取得**：指定列の値を上から順にカンマ区切りで取得する（絞り込みなし）。
- **キー項目 + フィルター項目指定で取得（フィルター指定は1種のみ）**：
  「列名 = 値」の条件に一致する行だけを対象にしてから、キー項目を抽出する。
  範囲指定・OR・複数条件の組み合わせ等はできない（対応するには要件を見直すか、
  レシピ側で複数の `filter` を重ねる設計を別途検討する）。

### from: DB（lookup）

- **キー項目のみ指定で取得**：指定テーブルから、キー列がCSV由来のIDのいずれかに一致する行を
  取得し、指定した取得列（例: `invoice_id`）の値を返す（絞り込みなし）。
- **キー項目 + フィルター項目指定で取得**：「列名 = リテラル」の条件を**複数個**指定でき、
  全条件を満たす行（AND）だけが対象になる（例: `logical_delete_flag = 0` で論理削除済みを除外）。
  CSVのフィルターと異なり、DB側は複数条件を同時に指定できる。
- **多段（連鎖）取得**：ある取得の結果を、次の取得のキーとして渡す連鎖ができる
  （例: 受注ID → order_detail_id → 売上ID の2段階）。各段は「単一テーブル・単一キー・単一取得列」
  のみで、段数に制限はない。

## 入力の不正検知・バリデーション仕様（テストで確認済み）

以下はコード（`src/lib/csv.ts` / `src/lib/lookup.ts`）とそのテスト
（`csv.test.ts` / `lookup.test.ts` / `lookup.integration.test.ts`）で確認済みの挙動。
ここに載っていない異常系（DB接続断など）はテストで担保されていない＝未確認。

### CSV（from: CSV）

| チェック内容 | 挙動 |
| --- | --- |
| データ行が1件もない（ヘッダーのみ） | エラー（「CSVに処理対象のデータがありません」） |
| 指定したキー項目の列が存在しない | エラー（存在する列名の一覧つきメッセージ） |
| フィルターが「列名 = 値」の形式でない（`=` を含まない等） | エラー（「filterは "列名 = 値" 形式のみ許可します」） |
| フィルターで指定した列が存在しない | エラー |
| フィルターに一致する行が1件もない | エラーにはならず、キー取得結果が0件（空）になる |
| 値が空文字や `"null"` という文字列 | そのまま値として扱う（特別扱いしない。空文字は空文字、`"null"`という4文字はその文字列） |

### DB（from: DB / lookup）

| チェック内容 | 挙動 |
| --- | --- |
| テーブル名・列名に英数字とアンダースコア以外の文字を含む（SQLインジェクション対策） | エラー（不正な識別子として拒否。バッククォートやスペースを含む文字列など） |
| 指定したテーブルが実際のDBスキーマに存在しない | エラー（「テーブルが実スキーマに存在しません」） |
| 指定した列（キー/取得対象/フィルター）が実際のテーブルに存在しない | エラー（「列が存在しません」） |
| フィルターが「列名 = リテラル」以外の自由記述（例: `1=1 OR 1=1`、`!=` 等の比較演算子違い） | エラーとして拒否（SQL断片の直接注入は不可） |
| フィルターで指定した列が実際のテーブルに存在しない | エラー |
| 入力キー（初期ID）が0件 | DBへ問い合わせず、取得結果を0件（空）で返す |
| 多段取得の途中の段で該当が0件になった | それ以降の段は実行されず、最終結果は0件（空） |

### 補足：なぜこの仕様か

- テーブル名・列名は実行時に**必ず実スキーマ（information_schema）で存在確認**してから
  SQLに埋め込む。値（IN句の中身やフィルターのリテラル）はバインドパラメータ化するため、
  レシピの宣言経由で任意のSQLを注入することはできない。
- フィルターを「列名 = 値／列名 = リテラル」の厳格な1形式のみに絞っているのも同じ理由。
  範囲指定やOR条件、比較演算子の違いなどを許すと自由記述SQLに近づき、
  安全チェックが機能しなくなるため、初期バージョンでは意図的に対応外としている。
