# 要件ヒアリング用 提出ガイド

新しいレシピ（Backlogに登録する定例のテンプレSQL＋パラメータ定義）を作る/直す前に、
以下の実物を置いてもらうと、AIが内容を推論しやすくなり、やり取りが減ります。
**プログラミング知識は不要**です。普段の作業で使っているファイルをそのまま置いてください。

## 置き方

`doc/requirements/<レシピ名>/samples/` を作り、以下を入れてください。

| ファイル | 中身 | 必須 |
| --- | --- | --- |
| `in.csv` | 実務で使っている入力CSV（数行でOK） | 推奨 |
| `manual.sql` | 手作業で実行しているSQL（あるなら丸ごと） | 推奨 |
| `out.sample.sql` | 期待する出力SQL（あれば） | 任意 |
| `procedure.md` | 現状の手作業手順書（あれば。手順がそのまま設計・図の元になる） | 任意 |
| `backlog.md` | バックログチケット・依頼内容の貼り付け（**Backlog連携が使えない場合の代替手段**） | 任意 |

さらに、テーブル定義を渡せる場合は **空ダンプ（データ無し）** を
`docker/mysql/dump/schema.sql` に置いてください。
（作り方の例: `mysqldump --no-data -u<user> -p <db> > schema.sql`）

## バックログチケットが元になっている場合

Backlog連携（MCP）が使える状態なら、`backlog.md`にコピペしなくても大丈夫です。
**チケットのキー（例: `WS-12`）かURLを伝えてもらうだけ**で、AIが直接チケット内容を読みに行きます。
接続できていない場合のみ、`backlog.md`に内容を貼り付けてください。

## 注意（重要）

- **本番の個人情報・機微データはマスキング**してから置いてください（IDや金額はダミー値でOK）。
- これらの提出ファイル（`samples/` と `dump/*.sql`）は **Git管理外** です。誤って共有リポジトリに
  上がらないようにしています。AIが整理した「要件シート」だけがGitに残ります。

## この後の流れ

置き終わったら「<レシピ名> の要件をまとめて」と依頼してください。
AIが提出物を読み取り、不足だけを質問し、`doc/requirements/<レシピ名>/<レシピ名>.md` に
要件シートを作成します。あなたはその内容が業務として正しいかを確認するだけで済みます。
要件が固まった後は、設計→実装（必要な場合のみ）→テスト→**Backlogへのレシピ登録**まで
AIが進めます（詳細は `.claude/skills/recipe-ops/SKILL.md`）。
